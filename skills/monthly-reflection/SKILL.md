# 한달기록 — 10분 자동 성찰 기록 스킬

매일 밤, 사용자는 **오늘 있었던 일(사실)** 하나만 적는다. 나머지 네 단계
**핵심감정 3가지 → 욕구 → 깨달음 → 부탁**은 스킬이 자동으로 채워 한 편의 성찰 기록을
완성하고, 완성된 기록은 **노션 "한달기록" 데이터베이스에 그날의 새 항목으로 자동 저장**된다.
이어서 같은 기록을 **네이버 블로그에 올릴 수 있는 글 초안**으로 다시 써서 보여주고, 노션의
"한달기록_블로그 발행" 페이지에 오늘 날짜 섹션으로 이어붙인다(데이터베이스처럼 행이 계속
늘어나지 않도록 페이지 하나에 날짜별로 모은다). **발행은 자동화하지 않는다** — 네이버 블로그는
외부 자동 발행 API를 제공하지 않으므로, 완성된 초안을 사용자가 직접 복사해 올린다.
이 기록이 하루하루 쌓이면 미사시 "나의 한달 기록 챌린지"의 한 달치 기록이 된다.

**목표: 부담 없이 10분 안에 끝낸다.** 사용자에게 여러 번 묻지 않는다.

## ⏱️ 10분 완성 원칙

- 사용자에게 요구하는 입력은 **딱 하나 — "오늘 있었던 일(사실)"** 뿐이다.
- 느낌·욕구·깨달음·부탁은 스킬이 자동으로 생성해서 바로 보여준다.
- 확인 기회는 **끝에 한 번만** 준다. 단계마다 되묻지 않는다.
- 전체 흐름: 사실 입력(2~3분) → 자동 완성 즉시 제시 → 가벼운 확인/수정(2~3분) → 완료

## 🔧 실행 순서

### STEP 1. 사실 받기
- 질문: "오늘 있었던 일을 편하게 적어주세요. 판단이나 해석 없이, 있었던 그대로만요. 여러 개여도 괜찮아요."
- 사용자가 감정을 섞어서 말해도 괜찮다 — 이후 스킬이 사실과 감정을 분리해 알아서 활용한다.
- 사실이 너무 짧거나 모호하면(예: "그냥 그랬어") 딱 한 번만 부드럽게 되물어 구체적인 장면을 얻는다. 그 이상 캐묻지 않는다.

### STEP 2. 핵심감정 3가지 자동 추출
- 사용자가 적은 사실 속 표현(직접 감정 단어 + 상황에서 드러나는 뉘앙스)을 함께 분석한다.
- 아래 [감정 단어 참고 리스트]를 기준으로 삼아, 가장 강하게 느껴졌을 감정을 **최대 3가지**로 추린다.
  - 사실에 없는 감정을 임의로 지어내지 않는다 — 항상 사용자가 적은 문장에 근거를 둔다.
  - 비슷한 감정어가 겹치면(예: "속상한"·"서운한") 대표 단어 하나로 통합한다.
  - 사건이 여러 개면 감정도 사건마다 다를 수 있다 — 그중 가장 두드러지는 3개만 남긴다.
  - 감정마다 근거가 된 사실 문장을 내부적으로 짚어두고 STEP 3~5에 활용한다.

### STEP 3. 욕구 자동 매칭
- 각 핵심감정을 아래 [감정 → 욕구 연결 가이드]에 따라 욕구로 치환한다.
- 여러 감정이 비슷한 욕구로 수렴되면 욕구도 통합해 1~2개로 정리한다. 억지로 3개를 채우지 않는다.

### STEP 4. 깨달음 자동 생성
- 사실 + 감정 + 욕구를 하나로 엮어, 오늘 하루에서 얻을 수 있는 알아차림을 1~2문장으로 만든다.
- 권장 형식: "오늘 나는 [사실] 때문에 [감정]을 느꼈고, 그건 내 안에 [욕구]가 있었기 때문이었다. [한 걸음 더 나아간 알아차림]."
- 훈계나 정답처럼 쓰지 않는다. 사용자 1인칭 시점의 자기 발견 문장으로 쓴다.

### STEP 5. 부탁 자동 생성
- STEP 3에서 찾은 욕구를 **오늘 또는 가까운 시일 안에 충족시킬 수 있는 구체적 행동**으로 바꿔 부탁 문장을 만든다.
- 원칙:
  - **구체적으로** — "잘 챙기기" (X) → "자기 전에 내일 할 일 3가지 적어두기" (O)
  - **긍정형 행동언어로** — "~하지 않기" 대신 "~하기"
  - **바로 실행 가능한 크기로** — 오늘~내일 안에 해볼 수 있는 작은 행동 단위
  - 대상은 나 자신일 수도, 타인일 수도 있음
- 욕구가 2개 이상이면 부탁도 욕구별로 하나씩, 최대 2개까지 제안한다.

### STEP 6. 결과 제시 + 가벼운 확인 (한 번만)
- [완성된 기록 포맷]으로 정리해서 바로 보여준다.
- 마지막에 딱 한 번만 확인한다: "혹시 다르게 느끼신 부분이 있으면 알려주세요. 없으면 이대로 완료할게요!"
- 수정 요청이 오면 해당 부분만 빠르게 반영하고, 전체를 처음부터 다시 묻지 않는다.
- 별다른 피드백이 없으면 그대로 최종본으로 확정한다.

### STEP 7. 노션에 저장
- 확정되면 바로 [노션 데이터베이스]에 오늘 날짜의 새 페이지로 추가한다 (notion-create-pages, parent는 위 data source ID).
- 속성 매핑 (이 순서로 채운다 — 있었던 일 → 느낌 → 욕구 → 깨달음 → 부탁):
  - `제목`: `M/D (요일)` (예: `7/23 (목)`) — 날짜는 여기 하나로 충분하므로
    별도 `날짜` 속성은 두지 않는다.
  - `있었던 일`: STEP 1에서 정리한 사실
  - `느낌`: STEP 2에서 뽑은 감정 단어 배열 (최대 3개)
  - `욕구`: STEP 3에서 매칭한 욕구 배열 (1~2개)
  - `깨달음`: STEP 4 문장
  - `부탁`: STEP 5 문장. 2개면 줄바꿈으로 구분해 한 필드에 담는다
- 저장이 끝나면 "🗂️ 노션 한달기록에 저장했어요"처럼 짧게 알려주고 STEP 8로 넘어간다. 저장 성공 여부를 사용자에게 다시 확인받지 않는다.
- 같은 날짜의 기록이 이미 있으면(재실행 등, `제목`이 `M/D (요일)`으로 겹치는 경우) 새로 만들지
  않고 기존 페이지를 덮어쓰도록(update) 확인 후 처리한다.

### STEP 8. 블로그 초안 생성
- STEP 7에서 저장한 오늘의 한달기록(있었던 일-느낌-욕구-깨달음-부탁)을 바탕으로,
  네이버 블로그에 그대로 올릴 수 있는 글로 다시 쓴다. 일기를 그대로 옮기지 않고
  **독자를 염두에 둔 짧은 에세이**로 재구성한다.
- 원칙:
  - **재구성하기** — 5단계 항목을 나열하지 않고, 기승전결이 있는 자연스러운 글로 풀어쓴다
  - **사생활 다듬기** — 실명·회사명·특정 가능한 세부사항은 일반화하거나 순화한다
    (예: "김OO 팀장" → "팀장님", 구체적 지명·상호는 생략 가능하면 생략)
  - **감정을 나열하지 않기** — "답답했다, 조급했다" 대신 그 감정이 드러나는 장면과 문장으로
  - **부탁·깨달음을 공감 포인트로** — 마무리 문단에서, 나만의 이야기를 넘어 읽는 사람도 공감하거나
    한 번 더 생각해볼 만한 메시지로 녹인다
  - **분량** — 본문 **1,200자 이상**. 에피소드를 더 구체적으로 묘사하거나, 비슷한 상황의 독자가
    공감할 만한 문단을 추가해 자연스럽게 채운다. 같은 문장을 반복하거나 억지로 부풀리지 않는다.
  - **제목(SEO/AEO 최적화)** — 오늘 기록의 핵심 소재를 담은 **핵심 키워드 1개**를 제목에 포함한다.
    사람들이 실제로 검색하거나 AI 검색·챗봇에 물어볼 법한 표현을 쓴다
    (예: "OOO 하는 법", "OOO 시작하는 이유", "OOO 후기"처럼 정보형·경험형 어구).
  - **키워드 반복** — 제목에 쓴 핵심 키워드를 본문 안에서 **최소 5회 이상** 자연스럽게 등장시킨다.
    문맥과 상관없이 억지로 끼워 넣지 않는다.
  - **도입부 요약** — 첫 문장에서 이 글이 무엇에 관한 글인지 핵심 키워드를 포함해 명확히 밝힌다.
    (검색엔진과 AI 요약·답변 엔진이 글의 주제를 바로 파악할 수 있도록)
  - **말투** — nightly-routine·misasi-challenge-notify와 같은 새벽거인의 말투: 담백하고 따뜻하게, 과장 없이
- [블로그 초안 포맷]으로 채팅에 바로 보여준다 (복사해서 바로 붙여넣을 수 있는 형태로).
- 발행은 절대 대신하지 않는다. "이대로 복사해서 올려주세요"라고 안내한다.

### STEP 9. 블로그 초안 노션에 저장
- ["한달기록_블로그 발행" 페이지]에 오늘 섹션을 이어붙인다 (notion-update-page, command: insert_content, position: `{"type": "end"}`).
  페이지가 아직 없으면 notion-create-pages로 그 이름의 페이지를 먼저 만든 뒤 같은 방식으로 채운다.
- 이어붙이는 내용은 아래 형식의 토글 섹션 하나. **본문·해시태그·상태 줄은 토글의 자식이 되도록
  반드시 진짜 탭(tab) 문자로 들여써야 한다** — Notion 마크다운 스펙(`notion://docs/enhanced-markdown-spec`)
  기준. `\t`라는 텍스트 두 글자(백슬래시+t)를 쓰면 안 되고, 실제 탭 바이트여야 한다. 들여쓰지 않으면
  토글이 빈 채로 접히고 내용은 페이지 최상단에 별도 블록으로 떨어져 나간다(실제로 한 번 이렇게 깨진 적 있음).
  빈 줄은 굳이 넣지 않아도 된다(Notion이 블록 간 여백을 알아서 준다).
  ```
  ## M/D (요일) — [STEP 8에서 만든 블로그 제목] {toggle="true"}
  <TAB>**상태:** 초안
  <TAB>[본문 문단 1]
  <TAB>[본문 문단 2 ...]
  <TAB>[해시태그]
  ```
  (`<TAB>`은 실제 탭 문자 하나를 뜻하는 표시일 뿐, 그대로 입력하는 문자열이 아니다.)
- 새 데이터베이스 행이나 새 페이지를 만들지 않는다 — 항상 같은 페이지 안에 날짜 섹션만 늘어나야 한다.
- 저장 후에는 반드시 notion-fetch로 다시 읽어 토글 안에 본문이 제대로 들어갔는지(빈 토글이 아닌지) 확인한다.
- 저장이 끝나면 "📝 블로그 초안도 노션에 이어붙였어요"처럼 짧게 알려주고 전체 흐름을 마무리한다.
